## Project

Personal portfolio for Abdoulaye Kemogoha COULIBALY (Full Stack dev, Abidjan). Single-page portfolio
plus an admin dashboard that edits all site content. Static UI copy is bilingual FR/EN (default
`fr`); content is French-first with optional English translations. The admin UI itself is
French-only. Code, identifiers, and comments are in English.

### Import alias — important

Imports use **`#/`** (Node subpath imports), NOT `@/`. e.g. `import { Button } from '#/components/ui/button'`.
Maps to `./src/*` (see `package.json` `imports` + `components.json` aliases).

### Project layout — feature-based

```
src/
├── features/
│   ├── data/         # data domain: types.ts, schemas.ts, defaults.ts (seed), storage.ts (JSON file
│   │                 #   export/import), portfolioQuery.ts, PortfolioDataContext.tsx, usePortfolioData.ts,
│   │                 #   localize.ts + useLocalizedPortfolioData.ts,
│   │                 #   db/ (client, schema, seed) and server/ (Server Functions, one file per entity)
│   ├── portfolio/    # public site sections, Navbar/Footer, hooks
│   ├── admin/        # dashboard: AdminLayout, AdminAuthGate, form modals, SortableList, inputs
│   └── i18n/         # messages/{fr,en}/*.json + localeRedirect (tested)
├── components/{ui,shared,layout}   # shadcn primitives / feature-agnostic presentational / app shell
├── hooks/  lib/                    # cross-cutting hooks; animations, cn(), constants
├── routes/           # thin route files composing features (index, admin/*)
├── router.tsx        # Paraglide URL rewrite
└── server.ts         # SSR entry wrapped in paraglideMiddleware
```

Imports use **specific file paths** (e.g. `#/features/data/usePortfolioData`). There are no barrel
`index.ts` files; they cause circular deps and `import/no-duplicates` churn. Routes are the only
place that compose several features.

### pnpm gotcha (already fixed, don't undo)

`pnpm-workspace.yaml` sets `verifyDepsBeforeRun: false` and lists `unrs-resolver` under
`onlyBuiltDependencies`. Without this, pnpm's ignored-build guard makes every `pnpm <script>` exit
non-zero (it also silently aborts `shadcn add`). If you hit `ERR_PNPM_IGNORED_BUILDS`, remove
`node_modules/.modules.yaml` and re-run `pnpm install` rather than reverting the config.

## Architecture — the parts that matter

### Data flow (read this first)

All editable content is one `PortfolioData` object (`{ personalInfo, skills, projects, experiences,
education, lastUpdated }`) stored across SQLite tables. Contact-form `messages` are a separate table
**outside** `PortfolioData`.

```
db/schema.ts (Drizzle) ◄── server/*.ts (createServerFn, Zod-validated) ◄── PortfolioDataContext
                                │                                           (useQuery + one useMutation)
              server/portfolio-data.ts (read, maps rows → PortfolioData)           │
                                │                                           usePortfolioData()  ── admin
              portfolioQuery.ts (shared key + fetcher) ─► __root loader      useLocalizedPortfolioData() ── public
                                                          (SSR prefetch)
```

Rules the codebase depends on:

- **`db/client.ts` is server-only.** Reach it only through `src/features/data/server/*` (TanStack
  Start strips Server Functions from the client bundle). Never import `db` from a component.
- **Components read content only through the hooks.** Public sections use
  `useLocalizedPortfolioData()`; admin uses `usePortfolioData()` (raw data, so both languages can be
  edited). Components never import `defaults.ts`; it is the seed/reset target, used only by the
  data layer.
- **Every mutation is a named `DataAction`** (`ADD_PROJECT`, `REORDER_PROJECTS`, `IMPORT_DATA`,
  `RESET_TO_DEFAULTS`, …) sent with `dispatch`. `runAction` maps it to its Server Function, and
  `applyAction` is the optimistic mirror applied to the query cache. Adding an action means updating
  **both** switches. Rollback happens on error and invalidation on settle, so the server stays
  authoritative.
- **Server Functions validate with Zod** (`.validator(schema.parse)`) and call `touchLastUpdated()`
  after each write. Callers never set `lastUpdated`.
- **Import** is validated twice: client-side in `storage.ts` (for a clear error) and again by the
  Server Function before `seedDatabase()` replaces everything. **Reset is destructive** (it
  overwrites the DB), so the UI must confirm first.
- **SSR**: the root route loader calls `ensureQueryData(portfolioDataQueryOptions)`, so first paint
  has real DB content (localized on `/en/`). `getDefaultData()` is only the fallback before data
  exists.

**Shape changes touch four layers that must stay in sync:** `db/schema.ts` (then `pnpm db:generate`
for a migration in `drizzle/`), `types.ts`, `schemas.ts`, and the row mapping in
`server/portfolio-data.ts` (and `db/seed.ts` when needed). `schemas.ts` enforces types ⇄ Zod
alignment at compile time with the `SchemaTypeChecks` `Equal<>` tuple, so drift fails `tsc`.
Migrations should be additive. `pnpm start` runs them on every boot, and the seed only runs on an
empty DB, so edited production content survives redeploys.

### Admin access

`/admin` (`routes/admin/route.tsx`) wraps everything in `AdminAuthGate`. The gate sends the
password to the `verifyAdminPassword` Server Function, which compares it to `ADMIN_PASSWORD`. A
granted session is kept in `sessionStorage` (`ADMIN_AUTH_KEY`). The gate is **client-side only**:
the mutation Server Functions do not check auth themselves. Keep this in mind when you add sensitive
endpoints. The admin head sets `noindex`.

### i18n (Paraglide) — read before touching UI copy

This is the officially tested TanStack Start integration; do **not** swap it for i18next.

- **Base locale `fr` is unprefixed** (`/`), **`en` is prefixed** (`/en/…`). The router `rewrite`
  (`src/router.tsx`) de-localizes URLs for matching and re-localizes generated hrefs, so `Link` and
  `navigate` keep the active locale on their own.
- **Detection order:** `url → cookie → preferredLanguage → baseLocale`. In SSR, `src/server.ts`
  runs `paraglideMiddleware`. Pass it the **original** `req`: the router does the rewrite, and a
  modified request gets de-localized twice and loops.
- **Messages:** `import { m } from '#/paraglide/messages'` → `m.nav_about()`,
  `m.education_item({ number })`. Never use a string key. Source files are in
  `src/features/i18n/messages/{fr,en}/<namespace>.json`. The runtime `m` namespace is **flat**, so
  prefix keys with the namespace (`nav_`, `hero_`, …). `src/paraglide/` is **generated** (gitignored);
  never edit it.
- **Module-scope `m.*()` is an SSR footgun.** It resolves once at import and leaks that locale across
  requests. Call messages at render time, and build locale-dependent objects such as Zod schemas
  inside the component. For label arrays, store getters (`label: () => m.x`), as `NAV_ITEMS` and
  `LEVEL_LABEL` do.
- **Content translation:** translatable fields have optional `*En` siblings (DB `*_en` columns,
  nullable). `localize.ts` falls back to French per field when the EN value is missing or empty, and
  per stat label for stats. To make a new field translatable, add the `*En` field in all four layers
  above, plus `localize.ts` and the admin form. Data-enum values (project `type`, skill categories)
  stay untranslated.
- **SEO:** the `index` route head holds the localized `<title>`/description, `hreflang` (lowercase
  key) and canonical. `<html lang>` is `getLocale()` in `__root.tsx`.

## Conventions

- **Container/Presenter:** presentational components only render. Data access and orchestration
  belong in hooks and containers. Extend a component through props (`variant`, `size`, `as`) instead
  of forking it.
- No magic numbers: put named constants in `src/lib/utils/constants.ts`. Comments explain *why* only.
- Animation: shared variants (`fadeUpVariants`, `staggerContainerVariants`) + `useScrollAnimation`
  (`once: true`). **Respect `prefers-reduced-motion` everywhere.**
- Theme: dark by default, class-strategy toggle. Accents blue `#3B82F6` / teal `#14B8A6`.
- Accessibility: WCAG AA contrast, full keyboard navigation, and an `aria-label` on every icon-only
  control. Images are lazy-loaded.
- **React 19 + Compiler:** do NOT hand-write `useMemo`/`useCallback`/`React.memo`.
